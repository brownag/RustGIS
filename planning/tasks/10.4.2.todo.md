## Notes
- **Q: How does panes.rs reach `external_complete`?** `panes.rs:879-881` takes `app.gp.web_run`
  (a GeoLibre browser slot) and calls `gp::external_complete`. It is the **geolibre** arm only.
  `panes.rs` never calls `r_complete`. grep for `r_complete` finds no hit in `ui-egui`.
- **Q: Where does the R arm complete?**
  - Native: `gp.rs:255` `run_r` calls `r_start` → `rustgis_r::default_runner().run` → `r_complete`
    → `finish`, all inside `Session::run` (`gp.runR` dispatch), so `guarded`'s catch_unwind
    covers it (`engine/src/lib.rs:559`).
  - Web: `ui-egui/src/lib.rs:109` `r_run: Option<...>` is `None` in `apps/rustgis-web/src/web.rs:608`.
    No R completion runs outside `Session::run` today.
  - So H3's claim that `r_complete` runs from `panes.rs:881` outside `Session::run` is wrong.
- **Q: Is the gp.rs comment the only thing relying on the inner guard?** Its comment is at
  `gp.rs:199` ("convert_output catches panics in the reader itself, so no guard is needed here").
  The native call is already inside `guarded`. The inner guard only changes the panic message
  (`Failed("the R result could not be read")` vs the generic "gp.runR failed unexpectedly").
- **Q: Session::run's last-resort guard.** It is inline: `engine/src/lib.rs:559`,
  `std::panic::catch_unwind(AssertUnwindSafe(|| f(self)))` inside `Session::guarded`
  (`pub(crate)`, a method on `Session`). It is **not** a free function. `ui-egui` cannot call it.
  Other guards are inline too: `analysis/src/lib.rs:288`, `gp.rs:510`.
  **No reusable helper exists.** This triggers the spec's STOP.
- **Q: Does the geolibre arm of `external_complete` have its own guard?** Yes:
  `gp.rs:510` `catch_unwind` around `rustgis_geolibre::finish`, with the comment at `gp.rs:508`.
  So the R arm is not the only unguarded one. It is the only one of the two with no guard in
  its own call path, and it is not reached from `panes.rs` at all.
- **Scope:** `gp.rs` is not in scope. The fallback edit is comment-only in `manifest.rs`.
