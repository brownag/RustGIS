## Notes
- Spec names `gp.locateR*`: no such command exists. The R commands in the engine registry are `gp.runR` and `gp.setRscript` (gp.rs:46-53, `#[cfg(feature = "r")]`). "Locate" is the UI-only `ui.locateRscript` (ui-egui lib.rs:1047), not in the engine registry, so hostile never reaches it.
- Hostile skip list (tests.rs:591-611) has no R id. Both R commands run with all six junk objects on world, raster and streamed sessions.
- Existing hostile junk has no `script` key, so `r_params` rejects it first. Nothing reaches R. The new junk keeps that property: `script` is not a string, or `inputs` holds null, both rejected before `r_start` stages anything or `default_runner()` runs.
- `gp.setRscript` junk: no hostile object has a `path` string that `choose` would accept. A `{"path": 7}` would call `choose(None)`, which resets the process-wide choice to default. Not added; flagged for the reviewer.
- Global state: `discover.rs` holds `CHOSEN` and `FOUND` as process-wide `static Mutex`es, and tests in one binary run in parallel. So no test here calls `choose` or sets env vars. `choose` refuses non-Rscript paths, so a "missing runner" cannot be set through it. `PATH` changes need `unsafe` (forbidden) and are process-global. The typed `RRunnerError::NotFound` path (item 4) is where a missing runner reaches the engine.
- `r_params` is `pub` (gp.rs:89), so items 2 and 3 need no R process.
