# 10.3.1 — Typed R notices

## Notes
Traced path of an R notice, with file:line:
1. **Emit (R):** `bootstrap.R:166,179,188` `.rgis_need()` calls `stop(msg)`; `bootstrap.R:229-239` (jsonlite missing) hand-writes `out/manifest.json` with `"error": <English>`. `bootstrap.R:105-118` `.rgis_run` turns the condition into `error` text via `conditionMessage`; `bootstrap.R:81-94` `.rgis_manifest` writes `error`.
2. **Parse (native):** `native.rs:69-118` runs Rscript (stdout/stderr to a log, `:91-92`). A non-zero exit gives `RRunnerError::Failed` (`:112`); a missing Rscript gives `RRunnerError::NotFound` (`lib.rs:64`, `native.rs:63-65`). Otherwise `native.rs:116` returns the files, and `manifest.rs:21-25` `convert_output` (with `catch_unwind`, which 10.4.2 handles) calls `convert_manifest` (`manifest.rs:28`). `manifest.rs:37-40` takes `error` and returns it as `Err(String)`.
3. **Sync path:** `gp.rs:222-230` maps `RRunnerError` to `String` (`Failed(m)` → `m`, other → `to_string()`), so the variant is lost here. `gp.rs:231` calls `r_complete`.
4. **r_complete:** `gp.rs:164` takes `ran: Result<RExecutionOutput, String>`; `gp.rs:182-184` maps `Err` to `"{R_FAILURE_PREFIX}{e}"` and converts the output. `gp.rs:185` pushes `PendingRun`. `gp.rs:68` defines `R_FAILURE_PREFIX`.
5. **PendingRun:** `engine/lib.rs:343-349` (`result: Result<ToolResult, String>`).
6. **Finish:** `gp.rs:502-507` `finish()` removes the run and calls `apply()`; `gp.rs:709-713` `apply()` returns `Err(e)` as `String`.
7. **Notify:** `engine/lib.rs:578` `Session::run` calls `notify(e, true)` on `Err`; `lib.rs:253-256` `Notice { text, error }`; `lib.rs:585` `notify`.
8. **UI:** `chrome.rs:211` (status bar) and `chrome.rs:545` (toasts) call `rnotices::translate(&n.text)` (`rnotices.rs:6-19`), which strips the prefix and matches the English text.

Also: `ui-egui/lib.rs:618,731` call `notify(e, true)` on `Err` from other paths; those stay `None`.

Constraints and risks:
- The `Err` channel is `String` from `apply()` to `Session::run`, so a typed notice cannot pass through it without a side channel. The spec's file list does not cover `finish`/`apply`, `Session::run`, or the `gp.rs:227` sync path. See Questions.
- `discover.rs:182` uses `NOT_FOUND` as a `String`. `discover.rs` is out of scope, so the English constants must stay (`english()` returns them).
- `manifest_tests.rs` and `harness_tests.rs` import `NEED_JSONLITE`; keep the constant names so they compile.
- No `unwrap`/`expect`/`panic` in the new code. `from_code` returns `Option`.
- The web build compiles `rustgis-r` with `manifest.rs` and `notices.rs` (not cfg'd); `RNotice` must not be behind a native-only cfg.
- Hostile params: the `notice` key in manifest is untrusted JSON; `from_code` must reject unknown strings.

## Questions
1. The typed notice needs a route past `finish()`/`apply()` (`gp.rs:502-713`), `Session::run` (`engine/lib.rs:578`), and the sync path (`gp.rs:222-230`). All are outside the spec's `r_complete`-only scope for gp.rs. Proposed: a `Session` field `r_notice: Option<RNotice>`, set in `finish()` from the `PendingRun` before `apply()`, and consumed in `Session::run`'s `Err` branch, so `Notice` gets `notice: Option<RNotice>`. Approve this widening, or name another route?
2. Keep `NOT_FOUND` and `NEED_*` as `pub const` (used by `discover.rs:182` and tests), with `RNotice::english()` returning them? Spec says to replace the constants; `discover.rs` is out of scope. Proposed: keep them.
3. The jsonlite-missing path already writes a manifest by hand (`bootstrap.R:229-239`). Proposed: add `"notice"` there, not the stderr `RUSTGIS_NOTICE:<code>` line the spec mentions. Confirm.
4. Should `convert_output` change its return type to `Result<ToolResult, RRunnerError>` (touches the `r_complete` call and `manifest_tests.rs` string asserts), or keep `String` and pass the notice through a separate typed result? Proposed: change to `RRunnerError`, with `manifest_tests.rs` assertions adjusted.
5. `Notice.text` keeps the English text (existing engine tests assert on `n.text`). Confirm.

- The side field is taken in `guarded` (where `notify` runs), not `Session::run`. It is taken on every path, which clears it on Ok.
